# Completion and turn usage

The user supplied DeepSeek Harness transcript and token-detail screenshots after the settings surface refresh. The conversation now follows that same visual language: softly tinted user bubbles, a neutral completion rule above the final answer, visible copy/usage/time controls beneath it, and an anchored accounting panel with a title total and aligned detail rows.

The completion row expands the existing execution process when one is available. Error and stopped result chips retain their existing messages and retry behavior. Copy continues to use the answer's Markdown source; timestamps show the time and retain the full date in their title. Existing copy and edit actions remain functional; this change does not introduce decorative feedback/share buttons.

The usage trigger opens a native non-modal popover with keyboard and outside-click dismissal. Its position is clamped to the viewport, and scrolling or resizing dismisses it. Uncached input, cached reads and cached writes are independent normalized buckets, counted once in the total. Unknown cache fields are omitted instead of claimed as zero. The panel shows the recorded model when known, not the composer's current selection; no provider route is inferred. Explicitly reported cost is retained in the detail view.

New shared-conversation results store `turnMetrics` with duration, requested model and reported cost. This small presentation record also travels with the live result. It does not change `runResult` error semantics, answer text, or model context. Older records use available usage without inventing a duration or model. The shared desktop conversation view uses the new surface across harnesses; native harness-owned pages and mobile clients keep their own renderers.
