# Agent 讨论：身份 prompt、工具与多种输入

更新：2026-10-02。用户确认“那就继续开发”后，已接入下述原生工具及附件路径。身份编辑继续保留；后文记录设计边界和验收要求。

## 当前交付和后续目标

本轮已把生产执行路径从文本策略切换到 `native-tools`，并接上附件、工具卡片、权限/提问弹窗和产物预览。首次发送仍检查所选模型连接；该检查是短文本连通测试，不等于对所有工具/插件的逐项验证。

- 六个 harness 复用普通聊天的原生 transport、配置解析及权限映射，模型/provider/订阅账号保持绑定。成员原生历史独立；旧文本成员首次执行工具任务时重建自己的上下文，公开群记录保留。
- 讨论与普通聊天共用 `chat-controls.js` 的附件、工具卡片和提问字段，以及 `file-preview-panel.js` 的文件预览。讨论支持选择文件、拖拽、截图粘贴、长粘贴转附件、移除/预览、纯附件发送和草稿恢复；Markdown、HTML、数据与其他文件预览沿用已有实现。
- 附件保存独立副本及 SHA-256；发送及执行前验证归属和内容。每条消息最多 16 个文件，每文件 32 MB、合计 128 MB；跨回合原生输入最多 256 个引用，图片另计上下文预算。删除群只清理本群附件副本，不删除源文件或工作产物。
- 每个群有独立工作目录和权限选择；同一目录中的原生工具任务逐个执行。即使选“并行”，文本历史仍固定在发送时，后执行的成员可能看到已写入的文件，输入区明确说明这一点。
- 原生审批按成员、delivery、run、request 路由；支持批准/拒绝、选择题与自由输入、暂后回答、停止后失效。工具过程保存在所属回复中；停止或重启后的未完成工具标记中断。成功产物可以预览，下一名成员可以实际读取。

目标是让每位成员具备所选 harness 在普通聊天中的实际能力，继续使用相同的输入、预览、工具卡片、权限询问和输出展示。保留六个 harness、现有 API/订阅、API 按 provider 选择、最多四名成员、并行/依次回复、独立群记录和 beta 标记。普通聊天与讨论的历史、原生会话和工作目录继续独立；复用组件及配置不等于互通历史。

## 已实现：成员身份

- 添加成员提供可选的「身份 prompt」，留空使用默认身份。可写身份、专长和回答方式，例如「你是一位科学家，重视证据并说明不确定性」。
- 点击聊天消息中的头像或名字打开同一编辑弹窗；成员面板也使用这个入口。支持取消、Escape、键盘操作，以及清空恢复默认身份。
- 身份属于成员 ID，相同模型的两名成员可以拥有不同身份。旧记录没有该字段时按空值读取，不要求重新建群。
- 保存仅更新该成员，不调用模型、不修改其他成员或过往消息。从下一次回复生效；该成员在准备、回答或排队时，先等其结束或停止再保存。
- 修改身份后复用既有配置变更生命周期建立新的原生上下文，重新带入公开群历史，避免旧身份仍作为原生指令留在上下文中。
- 发送时快照该成员自己的身份，作为用户提供的角色指令进入真实输入，并计入上下文预算；不会把其他成员的身份 prompt 当作指令发给它。权限和可用工具不由身份文字改变。

数据：Participant 增加可选 `identityPrompt`，每次 Delivery 保存其快照；旧 v1 记录兼容。输入最多 4096 字符；身份不进入连接指纹，因此编辑角色不会额外重复验证同一个模型连接。

验收：可选添加、头像/名字/键盘打开、取消/清空/保存、重启恢复、仅自己的身份入模、身份切换后保留公开上下文、忙碌时拒绝修改、中文/英文及深浅主题/窄窗口。

本轮验证结果：上下文、服务、管理器和存储相关 61 项测试通过；Electron 实际页面/IPC 测试及正常聊天布局对照通过，界面测试使用合成模型回复。另经 DeepSeek Harness + `deepseek-flash` 真实 API 实测，科学家身份返回 `ROLE_SCI`，修改为程序员后返回 `ROLE_DEV`，仍正确复述上一条用户消息的标记，并使用新的原生会话。这条真实证据不代表已逐一实测其余 harness 的身份回答。

## 工具和输入如何对齐普通聊天

| 能力 | 用户看到的行为 | 接入依据 |
| --- | --- | --- |
| 文本、代码、长粘贴 | 相同的输入框、代码展示和粘贴体验 | `claude.js` 输入/草稿流程、`clipboard-attachments.js` |
| 截图、图片 | 粘贴、拖入或选择；显示缩略图，可预览、移除 | 复用附件控件；由 harness 的真实图片输入能力和所选模型决定能否发送 |
| 文档、代码文件、数据文件 | 同样的附件卡片、文件预览、打开和定位；模型能读取选中的实际内容 | `file-preview.js`、普通聊天附件输入转换、原生读取/解析工具；预览成功不等于已经把内容送给模型 |
| 目录与工作文件 | 每个群自己的工作目录，工具在该目录工作；顶部显示位置 | `session-workspaces.js` 的目录选择/展示概念；不绑定已有单聊会话 |
| 文件、命令、搜索/网页及原生工具 | 每位成员回复下展示正常聊天的工具状态、参数、输出和失败原因 | 原有 session 事件、工具展示、权限映射；具体工具以当前 harness 原生能力为准 |
| MCP、skills、插件 | 复用已有配置及展示，保持成员归属和工具来源可见 | 现有配置解析与原生启动入口，讨论单独管理运行状态 |
| 生成的文件 | 产物卡片带成员署名，可预览、打开；下一轮其他成员可以引用 | `resolve-artifacts`、`file-preview.js` 与讨论附件存储 |
| 音频、视频等其他格式 | 普通聊天已支持的路径照常复用；未支持的组合明确显示限制 | 先核对原生输入能力，不把通用文件选择器当成音视频理解能力 |

不得把不支持的图片默默变成文件名后声称模型已看到图片，也不自动换模型、换 provider 或换订阅账号。混选成员中存在不支持当前输入的成员时，发送前标明具体成员和原因，保留草稿与附件，让用户调整成员或输入；不静默跳过成员。

## 分三步接入，每步可独立验收

### 第一步：原生工具、权限交互和工作目录

先让一名成员能在讨论中完成一次真实工具任务，再验证两名成员。对六个 harness 逐条复用普通聊天的启动配置与 transport，不再为正常工具能力另造一套引擎实现；先抽出可共享的主进程启动/配置函数，保留现有连接选择、native ID、私有历史和停止机制。

接入和验收对象如下，绑定范围以当前 `catalog.js` 为准。下表列出复用入口，不表示讨论中的工具和附件已经通过验收；每条绑定均需记录工具、文件读取、图片及审批的实际结果。不支持某项能力时记录明确原因，不用其他 harness 的成功代替。

| Harness | API | 当前订阅路径 | 复用的原生入口 |
| --- | --- | --- | --- |
| Claude Code | 当前 provider 目录 | 当前目录未提供 | `claude-session.js` |
| Codex CLI | 当前 provider 目录 | ChatGPT 订阅账号 | `codex-session.js` |
| DeepSeek Harness | 当前 provider 目录 | 当前目录未提供 | `dsh-session.js` / ACP |
| Kimi Code | 当前 provider 目录 | Kimi 订阅账号 | `acp-session.js` |
| Antigravity | 当前 provider 目录 | Google 订阅账号 | SDK API / CLI 订阅桥接 |
| Pi | 当前 provider 目录 | 当前目录未提供 | `pi-session.js` |

工具事件与停止是每条路径的必测项；文件读取和图片输入分别验证，不能相互替代。图片转换沿用第二步所列入口，并检查模型能力。交互审批依当前原生 transport 验证，具体例外见下文。这里不新增订阅登录体系。

需要同时完成以下工作，不能只删除 `tools: []`：

1. `production.js` / `text-runtimes.js` 增加正常工具运行路径，保留普通聊天现有 permission level 映射；默认采用正常聊天的询问模式。显式修改只作用于该群成员，不回写全局设置。
2. `capabilities.js` / `adapter-registry.js` 增加正常工具执行模式的证据与判定。原来的 `tool-free` / `workspace-read-only` 只描述现有路径，不能继续当成全部讨论能力的准入条件。
3. `native-adapter.js` 不再把所有 `gui:tool` / `gui:permission` 判为失败；使用成员 ID、Delivery ID、runId、requestId 路由原生工具事件和权限回复。复用普通聊天工具卡片、审批与提问组件，不把成员工具请求送到普通聊天的当前会话。
4. 用户可在输入附近查看本轮成员的权限。批准只回答原请求；停止、删除成员或运行 ID 变化后，旧请求失效，不作用于另一成员或下一轮。
5. 每群使用独立工作目录，群内成员共享它。可能写文件或运行命令的成员，按单次 Delivery 从开始到结束独占该目录；期间其他依赖此目录的读写任务均等待。没有写入者占用时，经执行策略核实为只读的成员可并行；身份 prompt 或模型自称只读不作为判定依据。纯文本、不访问工作目录的成员可继续并行。UI 明确显示「等待工作目录」。首版不实现复杂的逐文件锁。

Antigravity 订阅正式回复使用交互后台，可回传原生审批；旧 print-mode 仅用于受限连通性检查。每个 harness 只显示它确实能响应的选项，工具拒绝与等待人工审批必须分别呈现。

退出条件：在临时群目录中实际读取文件、展示工具结果、保存可见记录、停止并确认原生进程退出。支持交互审批的路径执行一次需要确认的命令并分别验证批准/拒绝；不支持交互审批的路径验证原生拒绝、清晰提示及没有无效批准按钮。双成员时审批不会串发，写入者不会与其他目录读写任务同时执行。验证上表六个 API 与三个现有订阅路径的代表性绑定，不穷举 provider 的每个 key。

### 第二步：正常输入框和附件链路

从 `src/renderer/chat/claude.js` 抽出附件选择、拖拽/粘贴、卡片、预览和草稿组件，普通聊天与讨论共用一份；沿用 `dsh:pick-attachments`、`dsh:save-clipboard-image`、`dsh:save-pasted-text` 和文件预览 IPC。

主进程为讨论附件保存受管副本和元数据，消息记录引用稳定资产 ID；原文件后来移动或修改时，历史仍指向发送时的内容。附件快照在入队前固定，同一轮 @ 的成员收到同一份输入。群删除及存储清理只移除不再被引用的受管资产，不删除用户原始文件。

图片使用 Claude/Codex/Pi 已有输入转换以及 ACP 的 `promptCapabilities.image`；连接和模型能力都满足才开放。文档和其他文件复用普通聊天的文件输入方式，在需要原生工具读取时按第一步的权限执行。纯文本策略仍保留时，只接受其确实能处理的文本/图片结构，不以文件路径绕过工具限制。

扩展讨论 schema：消息附件引用、Delivery 输入快照、模型输入内容块及附件预算。本轮使用 v1 可选字段兼容旧记录，旧文本原生 session 切换执行模式时退休并重建；不重写普通聊天 JSONL。后续长上下文摘要需保留图片/文件来源引用和关键工具结果，压缩后不能谎称仍持有被移除的附件全文。

退出条件：粘贴截图、拖入代码/PDF、文件选择、发送前预览/移除、纯附件消息、重启后恢复草稿与附件、两成员收到一致内容；不支持的组合在发送前说明，原文件移动后已发送记录仍可预览。普通聊天的原有输入回归通过。

### 第三步：群内工具协作与产物

工具完整输入/输出属于执行成员的过程记录；公开群历史只放成员最终回答、可分享的工具结论和产物引用，避免把大量日志和私有配置复制给其他成员。回复下使用普通聊天的折叠工具卡片，状态与实际事件一致。

依次回复时，后一名成员能收到前一名成员已完成的回答与产物；并行时，消息和附件仍使用发送时的快照，不注入该回合其他成员尚未完成的回复。这个快照不包含整个工作目录：共享目录的工具任务按第一步排队，后执行者可以看到前一成员已落盘的文件，UI 在选择回复方式时说明这一点。首版不增加文件系统快照或分支合并。新成员和上下文重建均从公开记录及有效附件引用补齐，不能复用另一个成员的原生历史。

停止保持现有进程归属检查；已发生的文件写入不会因停止而自动回滚。异常重启显示已完成产物及未确认状态，不自动重发可能产生副作用的工具操作。用户显式重试时先展示这些状态，从当前工作目录和已记录结果继续，沿用正常聊天的权限规则；无法核实是否已执行的外部操作不承诺绝不重复。

Goal、定时任务和会话控制类工具沿用现有显式用户授权要求。角色 prompt、群中引用、其他成员回答均不构成启动目标/任务或驱动其他会话的授权；不能因为开放一般工具而加入模型自动互相触发机制。

退出条件：程序员成员生成文件，评审成员读取同一产物并给出意见；权限和目录占用符合第一步规则，停止/重启不自动重发写操作，显式重试展示已完成及未确认状态；每个结果可以追到具体成员和输入回合。

## 复用位置与实施约束

- UI：`src/renderer/chat/claude.js` 的附件、工具卡片、权限队列、文件预览逻辑，`claude.css` 的设计元素；抽成共享模块后两页同时使用，不复制两份长期分叉。
- 主进程：`src/main/main.js` / `preload.js` 的附件与预览 API；新增讨论操作仍通过 `discussion-ipc.js` 的页面校验。
- 原生层：`claude-session.js`、`codex-session.js`、`acp-session.js`、`pi-session.js` 和 `permission-levels.js`；保留原生能力差异，不按 harness 名称猜测全部输入均支持。
- 调度与记录：扩展 `discussions/schema.js`、`manager.js`、`scheduler.js`、`native-adapter.js`、`context.js`，复用当前原子保存、独立成员、快照和 Windows Job 停止机制。

每一步以用户能执行的上述任务验收。现有文本讨论继续可用；逐路径接通工具后，再去除相应路径的文本限制文案。跨平台、远程群聊、超过四名成员及普通会话导入没有新增需求，不作为这些步骤的前置工作。
