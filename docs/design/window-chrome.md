# Desktop caption row

Windows desktop windows use a 40-DIP caption row with Application, Engine, Edit and View menus on the left and native caption buttons on the right. The row has the workbench's base color, follows the saved appearance and system theme, and shows no duplicate application icon or name. The OS window title remains available for task switching and accessibility. macOS and Linux retain their native window frame and menus.

The reference is the user's DeepSeek Harness screenshot and its public `apps/desktop/src/windows-layout.ts` at `ce7073d51254c26cd63b22a60835b8f948deb447`, which defines the same 40-DIP caption height. Camellia adapts that geometry to its existing Electron application menu.

`src/main/window-chrome.js` supplies hidden-titlebar options and a native titlebar overlay. Windows continues to own minimize, maximize, close, snap, resizing, drag and double-click behavior. The renderer only draws a draggable menu row. Clicking a menu opens the existing Electron submenu for that window; existing menu actions and accelerators remain registered. The IPC accepts only attached windows' main frames, not embedded settings views or foreign renderers.

The shared caption assets are used by Home, chat, Mobile access and CLI device windows, as well as the generated startup-error page. Settings uses the floating panel described below. Browser and headless pages add no frame. The row reserves native caption-button space, stays 40 DIPs at different page zooms, and releases that space in fullscreen. Alt or F10 focuses the menu; arrows navigate and Escape returns to the previous control without clearing a draft.

Settings opens as a frameless, transparent modal child of the workbench. Its renderer paints a 24px rounded surface, a draggable header and one close button, with no application menu or native caption buttons. It stays centered inside the workbench with a 24-DIP target margin (subject to native DPI rounding); large windows retain the existing content-size cap. A theme-aware backdrop dims the workbench until the settings window actually closes. The close button and Escape use the existing save-before-close path, including keeping invalid API edits open; nested dialogs and editable fields retain their own Escape behavior. Native engine settings continue to use the existing isolated embedded view. Browser-hosted settings retain their existing layout and have no desktop close button.

Windows caption buttons are outside the renderer's backdrop. While Settings is open, `window-chrome.js` composites their background and symbol colors using the same black mask as `--dsw-alias-bg-mask-1` in `ui-theme.css`. This state belongs only to the modal's owner, survives theme/menu refreshes, and is cleared after the settings window actually closes. Disposed parent contents are ignored during application shutdown.

Opening prepares the native caption and renderer backdrop before constructing the modal. The main process yields until the renderer acknowledges a painted backdrop frame, allowing native repainting to finish before window construction can block it. Settings then remains hidden until its own `ready-to-show`. Repeated requests during preparation are coalesced into one window with the latest destination, and repeated requests while it loads cannot show it early. A stale initial backdrop-state response cannot overwrite a newer open/close event. Paint acknowledgement uses animation frames, with no fixed-delay timer.

Validation: `tests/window-chrome.test.js` checks native options, main-frame authorization, popup coordinates, theme updates, fullscreen and platform behavior. `tests/window-chrome-ui.py` checks the actual chat renderer's menu keyboard interaction, translations, geometry and browser layout. `tests/window-chrome-electron.cjs` runs the isolated real application with hidden Windows windows and verifies the native overlay rect, menu IPC, theme, language, zoom, settings/chat/mobile layout, maximization and fullscreen. Native popup display is intercepted in that test to avoid opening menus on the user's desktop. Preview PNGs under `dist/ui-preview/window-chrome/` capture the renderer; Electron's native caption buttons are outside those captures. `tests/settings-close-electron.cjs` also verifies close/reopen and autosave, with its app-data path isolated explicitly.

The floating settings checks also verify transparent corner pixels, modal ownership, removal of native menus after appearance changes, backdrop removal after custom-button and Escape closes, a nested dialog retaining Escape, and small-window/zoom layout. `tests/settings-window.test.js` covers centering on primary/secondary monitor coordinates and capped sizes. `tests/settings-close-electron.cjs` exercises the actual custom close button for both valid edits and a failed save, then verifies saving on application quit. The existing `tests/native-settings-electron.cjs` passed with all five native DSH dropdowns reachable and persisted after reload, including embedded-view repositioning and disposal. Browser settings layout passed `tests/settings-page-smoke.py` in both languages, both themes and narrow widths.

The caption-color regression check records and forwards the real `setTitleBarOverlay` calls, then compares their background color with a sampled pixel from the rendered caption row in light/dark themes, while the modal is open, and after it closes. This catches the former white native-button strip that renderer-only screenshots cannot show. Unit checks also cover symbol colors, system-theme changes, per-window isolation and disposed parent contents. The regression reproduced `#ffffff` versus the rendered `#c2c2c2` before the fix and passed afterward.

The opening-transition check holds the acknowledgement after an actual backdrop frame, verifies that no modal has been constructed even after repeated clicks, and samples the caption while preparation is pending. After release it verifies one modal, a pre-dimmed native caption at construction, and showing only after readiness. Browser checks also deliver an old initial-state response after a newer open event and verify that a pending paint acknowledgement cannot bring back a closed backdrop. Hidden native QA windows retain background painting to exercise this handshake without displaying test windows.
