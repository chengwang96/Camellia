## 首版边界

v1 限 Windows 10+ 本地桌面，每群最多 4 名未移除成员、一个主题；仅 Codex / Antigravity 的 API、订阅与混用。讨论只接受输入/粘贴文本与代码块，成员和摘要均无工具。保留独立重复绑定、结构化 @、并行/依次、流式回复、停止、重启恢复和完整文本上下文；首页为 2×2 入口。

用户已明确：普通聊天的工作区、独立会话记录与 Agent 讨论暂不互通。首版共用七入口导航、布局与设计元素，各自保存群记录或单聊记录及草稿；不做工作区挂接、列表合并、历史导入、上下文传递或群与单聊转换。六个 harness 之间现有的共享会话机制仍按其原规则运行；无需为尚无需求的互通预先建设框架。

首版不读取用户工作区，不接附件、图片、MCP、shell、插件/hooks 或子代理，不开放文件修改。只创建独立成员会话并恢复本功能保存的历史，不导入旧单聊或外部原生会话。用户自定义状态目录/配置重定向不受支持；仍能被选定启动路径访问的共享状态必须隔离或明确拒绝，不能靠未扫描来源却返回 complete 放行。账号、线路和模型固定，改变绑定通过停止并移除旧成员、添加新成员完成。

文件工具、附件、其他 harness/平台、远程/手机、多主题、大规模优化与写入租约均延期。已有存储和监督代码复用，不重写通用框架。首版只按实施计划 V1-01–08 验收；尚未支持的核心双订阅依然是明确阻塞，不能用 API 或模拟结果替代。

## 目标与交互

用户创建讨论群，随时加入不同 harness、连接方式和模型的成员，通过 @ 指定谁回答。同 harness 多模型与跨 harness 订阅组合采用同一套机制。例如，一个成员通过 Codex 的订阅连接回答，另一个通过 Antigravity 的订阅连接回答；实际可选项以本机配置和适配器能力为准。

- 每个成员显示独立昵称、harness、模型、连接、推理设置及状态。@ 绑定稳定的成员 ID，相同模型可以有多个成员。首版最多 4 名未移除成员；存储中已移除成员的历史仍保留。
- 添加成员只保存配置，不启动推理。第一次 @ 时才准备其上下文。
- 没有 @ 的消息记入群历史，不自动调用模型；界面提示选择回答成员。
- 一条消息 @ 多人，默认并行独立回答；用户可显式选择按名单顺序依次回答。后者每人能看到前一人的完整回复。
- 模型输出中的 @ 只是文字，不会自动触发另一成员。首版没有自主轮转、自动争论或隐式 Goal。
- 移除成员停止其排队任务并取消其活动回合，保留历史署名；取消未完成前保留“正在停止”状态。

首版一个群对应一个讨论主题。数据模型预留 threadId，未来增加分支主题时，每个成员在每个主题有独立上下文；不把 thread 作为首版用户操作的前置要求。

## 架构与当前实现边界

采用应用侧讨论协调器，管理共享公开记录及各成员的独立原生会话。成员不需要通过 MCP 调用其他成员；Antigravity 订阅不暴露会话控制工具，不等于它不能被应用侧调度。

现有设施可参考：

| 位置 | 可复用的概念 | 需要新增或重新验证的部分 |
| --- | --- | --- |
| [共享会话](shared-conversations.md)及 `src/engines/shared-conversations.js` | 公开记录、驱动适配、原生会话、增量传递 | 当前单会话活动状态不能直接承载多个并行成员 |
| [绑定分段](model-switch-segments.md) | engine/connection/model/account 绑定与停车段 | 成员身份独立于绑定；相同绑定的两个成员不能共用原生会话 |
| [上下文容量](context-capacity.md) | 预算、原生压缩、可移植摘要及溢出识别 | 每成员预算、并行输入快照和摘要覆盖范围 |
| [会话工具](../conversation-tools.md) | 请求状态、取消与幂等请求 | 不依赖继承 engine/connection 的子会话接口实现跨 harness 群聊 |
| `src/benchmark/engines.js` | 多引擎调度经验 | Benchmark API 路径不能证明订阅路径、凭据隔离或只读权限已通过验证 |

保留普通单聊的数据和调度语义，新增讨论类型及协调器；不要全局把现有 `segments[engine]` 改成成员映射。当前已有按绑定停车/恢复机制，群聊扩展仍需独立的成员状态。

当前原生适配层每轮关闭进程，等待完整停止证明后释放会话池，下轮用原 nativeId 续聊，保留历史。现有 runId 标识进程，不足以区分同进程内的多个回合；独立进程 generation 配合 Delivery 身份用于隔离迟到事件。启动前的实际限制、启动后的绑定核查和完整停止证明都必须由可信执行策略提供，缺失时默认不可用。`shutdown()` 返回、`dead` 标志或模型 result 都不能单独证明子进程已停。此策略尚未在真实连接实现和验收。

讨论策略的 `prepare` 接收本轮 identity，返回完整成员 settings、同步 `launch.buildSpec` 和受监督 `launch.spawn`。`native-launch.js` 用不可序列化的进程内凭据把这些设置固定到运行 ID、目录和原生 ID；Codex/Antigravity 不再使用普通启动默认值，也不回写全局 connection。订阅账号明确固定并核查续聊连接；Codex 不按配额换账号。凭据在停止核查及释放后撤销。此接口本身不构成只读控制或后代停止证明，生产策略仍未实现。

Antigravity SDK 的显式 executionPolicy='tool-free-v1' 是执行限制入口，独立于普通原生配置与 permissionMode。主进程和桥接分别核对 SDK 0.1.17；空工具白名单、关闭子代理与执行前统一拒绝共同生效，MCP/skills 配置、ACP MCP 注入和提升模式被拒绝。没有该参数时普通聊天保留现有行为。原生本地探针核实了实际工具名、强制调用拒绝、零工具目录、工作区不变和重启续聊，仍未组合为可注册的完整生产策略。CLI 裸 deny=["*"] 的旧拒绝结论已撤销。正确 action(*) 规则已在固定运行时核实五类拒绝及原生续聊，但仍启动 profile/工作区 MCP；空工具主 Agent 也仍暴露 MCP/任务工具。配置隔离、hooks 和其他副作用路径未完整验证，不能据此开放核心订阅组合。

Windows 10+ 监督基础 `windows-job.js`/`windows-job.cs` 已通过本地实进程测试：目标在创建时加入独立 Job，关闭 breakaway；停止先封闭启动，再终止并查询 Job 活动进程为零，最后等待监督器退出。stdout/stderr 通过数据帧传递，不能伪造控制证明。主进程退出时仍清理 detached 子孙；监督器失联时，系统清理不能直接被应用当作已核实证明。当前没有其他平台实现或生产连接验收；本地 CLI/SDK 探针仅验证存储布局与生命周期。Job 负责 CreateProcess 后代生命周期，不提供文件只读或外部副作用限制，仍须由生产执行策略补齐。

每次 Windows 启动须先用 `WindowsJobJournal` 独占创建持久化身份记录；同一 Delivery 不重用，损坏记录不覆盖。`recoverWindowsJob` 在与 Job 创建和目标启动共用的文件锁下，先 flush 永久封闭标记，再查询本轮全局命名 Job。恢复后迟到的旧监督器不能初始化或派发；缺失、损坏、身份不符及访问失败均保留限制。记录和封闭标记本身都不是停止证明，也不能被清理作业当作缓存删除。应用存储约定为 `discussions/windows-jobs/<deliveryId>/`；清理器已保留这些记录、锁、封闭标记及对应运行目录，普通入口也独立检查启动记录中的运行 ID。独立恢复器已通过本地测试，主进程启动恢复仍待接线；其结果不含 released，调用方须另外核查资源释放。

原生策略一旦进入 prepare，就承担停止核查义务；准备抛错或返回的绑定被拒绝，也不能跳过已分配监督器等资源的排空。未取得对应回合的 confirmStopped 时保留活动槽与归属。

原生归属独立于会话池槽位：不同运行 UUID 也不能接入同一 harness 的同一原生历史。`native-ownership.js` 在启动准备前保留身份，在异步准备、验证及派发之间重查；停止释放活动占用后仍保留历史所有者。`native-inventory.js` 已合并其他讨论群、已移除/退休成员、普通会话磁盘与内存的当前/停放/退休段、全部保留池项、应用历史镜像和启动记录。不能只用会忽略坏索引的单聊 `.items`，也不能把 dead 当作归属释放。同步扫描有数量/字节上限并核查扫描中变化；损坏、链接或部分来源均拒绝。Windows journal 无法唯一匹配持久化 Delivery 时，运行 ID 保留为所有引擎的外部占用。`native-access.js` 已在桌面与 CLI 服务端六个引擎的普通入口安装反向检查：同步读取持久化讨论和启动记录、核查池中讨论活动，拒绝复用讨论群 ID、运行 ID 和同引擎原生 ID。池释放后、重启后、已移除及退休历史继续受保护，原生历史的普通删除入口也受同一检查。损坏记录不能按空库存处理；无讨论目录时普通入口无需创建目录。Windows 文件 ID 按不区分大小写检查。

反向入口只接受准确且未撤销的进程内启动凭据走讨论路径，不能通过 IPC 标志绕过。SessionPool 直接替换或清空讨论槽也须匹配所属凭据；普通 release 不能释放其资源，整体 shutdown 保留讨论句柄。桌面 `native-boundary.js` 已把共享归属实例、清单、空注册表与反向检查接到一起，未持久化的原生 ID 在池释放后仍受保护。首次保留及每次准备后重查都记住已观察到的外部 ID；新开进程只能解释本轮新镜像，不能夺取此前外部归属。Codex 标准目录与显式重定向、Antigravity 桥接/存储拓扑读取已实现；存储身份准入/持久化/反向接口及无输入准备已有本地证据。全部配置层/历史重定向、所有外部目录与活动的完整覆盖仍未接通。因此完整原生来源回调仍未注册，缺少明确完整清单时拒绝正向派发；镜像不构成完整原生覆盖。这是应用边界，不是外部 CLI 的操作系统锁。

`codex-history-inventory.js` 保留原始索引中归档、未命名、子会话及缺失 rollout 的 ID，另读活动/归档 rollout 的有界元数据首行，不能复用桌面导入 UI 的过滤列表。SQLite 在主文件/WAL 的独立临时副本上只读核查；Windows 活动 SHM 不复制，避免字节锁。并发修改、未知布局、链接、元数据不符、跨 home 同 ID 或超限都拒绝。标准应用路径包括 API 的独立运行目录、默认及其他账号、孤立目录。读取 home 配置、内嵌/独立 profile 中的绝对 sqlite_home，同时保留默认目录；调用方显式提供 configFiles/sqliteHomes，以覆盖额外配置层和已解析的环境/命令行目录。相同 home 合并声明，相对/~ 配置、缺失显式文件和扫描期间变化拒绝。CLI 0.154.0 已本地验证环境相对路径按 cwd 解析、配置优先；这些接口不代表已发现全部外部来源。仅创建未派发的线程可能尚无磁盘 ID，运行中池/归属仍须保留。

`antigravity-history-inventory.js` 返回桥接 nativeId、连接、storageDir 和底层 conversationId；存储作用域不能在归属判断中省略。SDK fork 复制独立目录，底层 ID 可相同；同一 CLI 目录的两个桥接 ID 却可恢复同一底层历史。读取器合并 SDK/CLI 数据库、完整 CLI conversation_summaries 索引及关联 ID、孤立 brain/annotations/presence 引用，保留未派发桥接和缺失文件的记录。CLI 的数据库名按 cascade_id 核查，不把内部 trajectory_id 当作 conversationId；索引的 antigravity-cli 命名空间也与绝对路径分开核查。文件/WAL 读取有界，SQL 只在临时副本执行，链接、部分记录、重定向和变化均拒绝。该结果没有 complete 声明，旧缓存/protobuf 索引和全部外部来源仍待核实；拓扑经 native-storage.js 投射到原生归属，停止后保留内存身份，started 原子保存成员及 Delivery 的 nativeStorage，退休/移除和重启读取继续保留。正向 Antigravity 派发要求输入前的当前存储映射，普通入口通过可信同步回调排除别名；未配置来源且存在受保护历史时拒绝相关续聊/删除。Antigravity 专用 session/camellia_prepare 在输入前分配并保存身份：CLI 等待 init；SDK 建立连接后核对独立目录的唯一数据库 ID，并由主进程校验 SQLite 身份。准备返回值须与当前归属相同，随后同步保存 started 才可发 prompt。准备后禁止改会话/模型/模式；失败、取消或停止不自动重试。零输入重启和准备期间关闭已本地验证，生产回调/执行策略仍未配置，不能据此宣称生产隔离已验收。

映射记录与当前数据库证明分开处理：只有实际对应数据库通过核验，读取器才返回 databaseVerified，投射层据此给出 storageVerified。数据库缺失、只有 summary 或父级/cascade 引用、旧拓扑缺少证明字段时，不允许认领或继续发送；它们仍保留原生归属，不能因文件消失而交给另一个成员。已确认的存储身份会持久化，核验标志每次从当前可信来源重新取得。

空间清理读取 `discussions/<groupId>.json` 的完整引用，保留当前、已移除和退休成员的运行目录、原生 ID、摘要及附件。清理预览不是永久授权：执行前重读记录，连原先不存在的目录也核查是否新出现；无法读取、部分启动记录或扫描中变化均停止删除。快照和启动记录不作为缓存候选。群删除、摘要归档及 P3 新增资产的生命周期仍须随相应功能继续接入。

`adapter-registry.js` 只由可信主进程配置，复制固定绑定及运行时/策略版本的已核实证据，默认没有任何生产条目。撤销注册取消准备及运行中的活动，完整停止前不能注销或替换；旧事件继续被消费。跨注册保留同一运行 ID 的进程 generation，禁止驱动计数重置后误认旧输出。桌面已在普通单聊前调用注册表分流事件；调度器可从该注册表取适配器，但生产条目和协调器均未启用。正向模拟测试不构成真实能力证据。

账号、网络和运行时配置变更须先安装调度准入限制、排空相关活动和队列，再变更并显式解除限制；不同范围的限制独立保留。读取失败、缺停止证明和重启残留未核查都不能解除限制。没有 @ 的记录仍可保存；恢复连接不重发已取消的请求。退出使用永久的全局限制。内部 `suspend`/`drainSuspension`/`resume` 已测试，设置与退出处理器的应用接线仍待实施。

## 数据模型与不变式

P1 存储落地：每群一个版本化 JSON 原子快照，包含逻辑上仅追加的消息记录、成员与 Delivery。通过同一次 flush/rename 提交回复、完成状态及游标，避免三者跨文件部分提交；重启忽略未提交临时文件、将未完成请求标为 interrupted。普通单聊 JSONL 不变。此实现是主进程单写者，完整历史重写的成本后续按实际规模评估；迁移至日志存储时须保持同等提交语义。

当前 v1 schema 对群、成员、当前/退休 session、请求、公开消息、Delivery、输入和 settlement 使用严格字段及关联检查。拒绝未知字段、错误署名/指纹/串行 retry 链、结果与游标不符、原生代际/绑定/存储身份混用，以及含未来回复的原生上下文。写入同时保护已发布日志和既有请求身份；幂等重取不写盘，异步 callback 或不可复制结果不能先提交再报错。P3 加入摘要、附件及预算时须明确扩展版本与校验；当前文本格式不代表这些功能已经完成。

单群快照读、列举、写入共用 32 MiB 上限；磁盘字节包括缩进、换行和 UTF-8。公开消息与回复各 256 KiB、固定 prompt 1 MiB，字符串上限包括 JSON 引号/转义，超出即明确失败。每群最多 64 个保留成员、128 个未结束 Delivery、10000 个请求、20000 条消息及 20000 个 Delivery；每成员最多 1024 份退休 session。库存最多 1024 群、目录 4096 项、256 MiB。限额不会触发静默截断或清除历史，也不作为模型上下文窗口。

准入阶段为已启动活动预留输入、部分回复、待提交结果、公开回复与退休元数据；新消息不能占用这些收尾空间。启动容量不足的排队项明确失败；最终答案过大时在冻结成功结果前失败并排空，不留下无法提交的成功意图。读取在同一文件描述符上限制分配和字节量，复查文件身份与扫描变化，拒绝硬链接、链接根、坏 UTF-8/JSON；空间清理复用此读取器。同步全量快照和库存校验的规模性能仍需后续验证。

下列为概念字段，不要求直接作为最终存储格式：

| 对象 | 关键字段与含义 |
| --- | --- |
| Discussion | id、cwd、threadId、成员列表、递增 seq、公开日志、写入策略 |
| Participant | id、昵称、engine、connection、model、accountRef、thinking、context 配置、生命周期状态 |
| MemberSession | participantId、threadId、generation、nativeId、bindingFingerprint、coveredThroughSeq、nativeOwnMessageIds、summaryRef |
| Message | id、seq、threadId、speakerId、类型、正文、附件引用、requestId、完成状态 |
| Delivery | requestId、participantId、generation、inputThroughSeq、输入消息 ID/摘要引用、配置版本、状态、结果 ID |
| Summary | id、版本、threadId、覆盖区间、来源消息 ID、正文、生成模型、用量与状态 |
| WorkspaceLease | 规范化目录、持有 requestId、权限范围、状态、取得与释放时间 |

accountRef 只引用现有账户配置，不复制密钥。首版不提供原成员直接更换绑定：先停止并确认当前活动，移除旧成员，再添加具有独立身份的新成员；旧公开历史和署名保留，不跨模型、账号或 harness 恢复原生会话。未来若开放原位改绑定，才需新增 session generation 和相应编辑流程，该界面不属于首版。

核心不变式：

1. 公开日志是讨论中“谁说过什么”的依据；成员观点不自动成为已验证事实。原生会话和摘要都是可重建的派生状态。
2. `coveredThroughSeq` 表示当前原生状态已通过原文或标注摘要覆盖的连续日志前缀，不代表模型准确记住了全部内容。
3. 每成员同一时刻至多一个活动请求；准备、摘要、审批和取消也占用该成员。
4. 并发回合只能确认自己实际收到的输入快照，不得在完成时直接使用群的最新 seq。
5. 成员原生状态、取消信号和权限绑定到成员与 requestId，迟到事件不能更新新 generation。

## @ 时的上下文投递

协调器先持久化用户消息和目标成员，再为本轮固定 `inputThroughSeq`。

1. 读取该成员当前 generation 的覆盖游标，选取 `(coveredThroughSeq, inputThroughSeq]` 内本主题可投递消息。
2. 按成员预算构造输入：群规则和身份、已固定的用户约束、必要摘要、近期原文、当前请求。当前请求只放一次。
3. 他人发言明确标注 speakerId、昵称和消息 ID，作为讨论材料注入。只有本轮用户请求决定本轮任务；引用的指令、工具输出和历史任务不能自行触发执行。
4. 自己的发言只有在“确认已存在于当前 generation 原生会话”的情况下才省略；新建或恢复不确定的原生会话必须带回所需的旧发言，标注为历史发言。
5. 记录 Delivery 的准确输入范围，启动该成员；完整回复持久化后，用同一可恢复提交步骤记录结果和确认的覆盖范围。
6. 完成时至多推进到 `inputThroughSeq`。本轮自己的输出另记入 `nativeOwnMessageIds`；下次跨过这些行时可省略正文，但不能跨过未投递的他人消息。

示例：群已有 seq=40，@A @B 的用户消息为 41，两人的输入上界都为 41。A 的回复为 42，B 的回复为 43。完成后两人的覆盖游标均为 41；下次 A 应收到 B 的 43，并省略原生会话已有的自身 42。不能因为 A 或 B 后结束，就声称它见过对方本轮答案。

串行模式在前一成员成功提交后再固定后一成员的输入上界；前一成员失败时暂停剩余队列，由用户选择跳过或重试。并行模式各成员使用相同公开输入快照，但既有私有原生历史可能不同，因此不宣称这是严格等条件评测。

模型工具调用、内部推理与原始大段工具输出不广播。公开回复、用户可见的工具结果摘要、相关文件变更和附件引用可以入群记录；工具结果必须保留来源和时间，避免把旧文件状态当成当前事实。

## 重点一：首版无工具与后续文件操作

首版仅运行无工具文本模式，不选择工作区读工具或执行成员。以下只读工具和唯一写入者是后续版本设计；不能把全应用写入互斥提前作为 v1 发布条件。首版仍必须核实无工具策略、扩展不启动、专属状态与停止行为。

### 后续工作区只读必须能够执行

讨论默认只读：成员可阅读被允许的文件、返回建议或展示补丁文本，不能修改工作区、执行有副作用的命令或通过外部工具写入数据。提示词只是补充说明，实际约束必须由适配器的工具策略、权限控制或受限运行环境落实。

启动前检测该 harness/connection 是否能够落实所需限制。若无法限制任意 shell、文件工具或有副作用的 MCP 工具，则该组合不能以“只读成员”身份进入工作区执行；只有适配器能提供无工具文本模式时，才降级为仅接收选定材料的文本讨论。两者都不支持则明确标为暂不支持，不能静默放开权限。

只读指用户工作区与外部副作用；引擎自身日志和会话存储可写入其专属状态目录。工作区中的测试、构建命令也可能写文件，不能仅凭命令名把它们归为只读。

配置/扩展启动同样属于执行边界。CLI 1.2.3 的原生 action(*) Deny 不阻止 profile/工作区 MCP 进程启动；自定义主 Agent 的 tools: [] 仍暴露 MCP 与任务管理。因此必须另行验证专属 profile、工作区配置、插件/hooks 和残留工具，不能把一次文件拒绝、空 tools 配置或无模型请求等同于没有副作用。CLI 文字投递使用显式 literalInput 时，不兼容的原生 plan 等模式在桥接处直接拒绝；文字原样投递不授权任何工具。

### 后续显式执行回合

用户可指定某成员执行修改。该授权限定成员、工作区、任务和回合，不给其他成员或后续轮次长期写权限；原有工具审批机制继续适用。

- 协调器在启动写入回合前取得应用级工作区独占租约。键按规范化真实路径判定，同目录和父子目录重叠均视为冲突。
- 同一应用的普通会话、其他讨论群等写入入口必须参加同一租约机制，才能承诺应用内唯一写入者。接入完成前禁用讨论写入功能。
- 不通过多个可写原生会话加提示词来模拟互斥；未获得租约的写入任务排队，不能先启动再等待。
- 首版写入期间暂停其他成员的工作区工具回合；已有读工具回合结束后才授予写租约。这样减少读到修改中间状态的情况。纯文本回复可继续，注明其依据的文件版本。
- 切换写入者须等待前一回合、工具进程及可能持续写入的子进程确认停止。不能仅靠租约超时释放锁。
- 取消不回滚已经写入的文件。停止后记录已知修改、校验状态和仍不确定的副作用，再允许下一位接手。
- 重启后未确认终止的执行记录标为需恢复核查，不自动恢复写入或转交租约。

该锁只协调 Camellia 管理的操作，无法阻止编辑器或其他应用改文件。写入前后记录相关文件哈希或版本状态；发现外部变化时要求重新读取，不能把已过期补丁直接覆盖。未来可增加独立 worktree 或副本，但 fork 原生会话不提供文件隔离。

写入完成后，群内发布变更文件、实际检查结果及未完成项。其他成员下次引用这些文件时重新读取，不能只信上一轮工具缓存或摘要。

## 重点二：每位成员独立上下文预算

不能用群统一窗口，也不能把群规模直接换算成“必定 N 倍上下文”。实际增长取决于发言长度、调用频率、工具记录、已有上下文及压缩策略。

每次调度按目标成员重新计算：

```text
历史可用预算 = 有效上下文上限
             - 当前原生会话已占预算
             - 本轮固定提示及工具定义开销
             - 当前用户请求与本轮附件预算
             - 输出预留
             - 安全余量
```

各项必须定义为互不重复的预算：原生用量若已含固定提示/工具定义，不再扣一次。请求级输入上限还要单独约束完整输入。新 session 的历史占用从零计算，但仍需扣除实际固定开销。

首版仅有文本输入，附件预算为零，工具调用禁止；隐藏的原生协议开销仍需计入固定开销或保守余量。不能为完善未来附件估算而延迟文本预算与摘要接线。

- 有效上限按该成员实际绑定的配置、目录声明和可靠的明确限制确定；不能拿其他成员或其他账号曾成功的请求当作本成员上限。
- 原生已用量优先采用驱动报告；缺少数据时保守估计并标注为估算。工具定义、隐藏原生开销和图片成本无法准确获知时扩大余量，不宣称精确剩余 token。
- 优先用适用 tokenizer；否则使用保守的文本估算，中文、代码和附件不能统一按“四字符一个 token”保证可装入。
- 当前请求、关键约束或单个附件已超预算时，提示缩短或选择材料；不静默截断，不自动替换模型或账号。
- 只有确认的上下文溢出才触发容量恢复；速率限制、鉴权错误和输出预算错误不应触发摘要循环。

例如 A 的窗口较大、B 的窗口较小：A 可以接收较长原文，B 使用覆盖相同历史范围的摘要与近期原文。界面明确显示两者输入形态不同，不能声称它们获得完全相同的细节。

## 压缩、摘要与新成员

采用以下决策顺序，每一步后重新检查目标预算：

1. 原生会话可继续且增量装得下：直接补齐增量。
2. 原生会话占用过高、该绑定支持可靠原生压缩：先压缩已有状态，再尝试装入未读。原生压缩不能压缩尚未送进去的未读历史。
3. 未读过多：分块摘要较早的未读，保留近期原文和当前请求。每份摘要有精确覆盖区间，摘要区间与原文区间不得重叠或遗漏。
4. 原生会话不可恢复、压缩不支持或仍装不下：从公开日志构造新 generation 的上下文，验证预算后再切换。摘要失败保留原状态，不先销毁可用会话。

摘要内容保留：用户目标与约束、明确决定、每个成员的关键主张与分歧、未解决问题、证据出处、文件版本/修改情况。不得把多数意见写成验证结论，也不能把尚未执行的建议写成已完成工作。

摘要由协调器安排模型生成，仍消耗所选模型的额度或 API 费用。首版使用被摘要成员相同的模型、固定连接和账号，记录执行者与用量；不新增多摘要器配置界面，不暗中换提供商。没有可用且已获授权的线路时暂停该成员并提示具体原因。仅订阅用户通过同一订阅生成摘要，无需另配 API。摘要也使用无工具策略并纳入取消/停止生命周期，不产生群成员发言或自动 @。

可共享同一主题、同一覆盖范围的摘要作为派生缓存，但发送前仍需适配每位成员的目标预算。摘要生成模型的输入窗口与接收成员的输出摘要预算分别计算；采用有请求数、层数和总量上限的分块合并，失败不无限递归重试。源记录保留，用户可查看摘要及覆盖范围；摘要不保证无损。

新成员首次被 @ 时默认收到本主题截至输入快照的摘要与近期原文；历史足够短则全量原文。固定用户约束单独保留；关键原文可由用户显式附带，超预算时明确提示。不会复制其他成员的内部推理、原生状态或工具权限。

未来多主题必须使用 `(participantId, threadId)` 独立 session，禁止仅按 threadId 过滤消息却继续复用已混入其他主题的 native session。跨主题引用需要显式选择材料并记录来源。

## 失败、取消与持久化

Delivery 状态为 queued → preparing → running → completed，异常进入 failed / cancelled / interrupted。preparing 下的 context/summary 与 running 下的 answer/approval 是活动子状态；取消活动进入 stopping，确认完整活动停止后才能 cancelled。取消必须传递到摘要任务、驱动和排队调度。部分公开文本存于原 Delivery，不作为完整回复传播。串行失败显式 skip 保留原终态，retry 插入独立尝试并保留旧记录及操作 ID；未成功或跳过前，后续成员仍暂停。

- 持久化 requestId 和输入计划后再派发。同一 requestId 不得重复创建任务或重复追加回复；用提交标记恢复日志、结果和游标的部分写入。
- 获取结果后固定 settlement，先保存公开正文，再等待活动停止和资源释放，最后原子提交回复、终态与覆盖游标。停止证明须对应本轮 runtimeId/deliveryId/generation；同一原生会话上一轮证明不能复用。成功与失败均不能只凭 result 或 cancel 返回释放成员槽。
- 停止核查或提交失败保留原 settlement 和活动句柄，显式复查只重试核查/提交，不重发推理，也不把已取得的成功结果变为取消。同成员队列和串行后继在不确定性解除前不得启动。重启保留 settlement 但将活动标为 interrupted，不自动发布待提交结果；恢复界面和实际残留核查仍待接入。
- 请求失败不推进覆盖游标，但这不代表原生引擎没收到输入，也不代表工具没有执行。不得因游标未推进就自动重投。
- 原生状态不确定时，先读取适配器可验证的状态；无法核实时退休该 generation，并在用户重试时从已提交公开历史重建。可能有副作用的任务还需核查工作区和执行记录。
- 中断的流式文字在 UI 标注未完成，默认不作为完整答案投递；已确认的文件副作用仍需进入恢复记录。
- 单个成员失败不取消其他独立并行成员；“停止全部”先设置进程内准入限制并尝试持久化停止意图，再取消所有活动及排队回合。写盘错误必须报告，但不能阻止已知活动接收取消。确认完成前阻止新的模型调用，无 @ 的记录仍可保存。
- 移除意图在等待停止前持久化；写盘失败时进程内移除限制仍生效，期间不能再次 @ 或改成员绑定。确认完整停止前保留成员，避免等待期间新增任务绕过移除。
- 事件保存失败必须由协调器记录并中止活动，不能依赖驱动传播回调异常；异步 UI/日志观察器异常不能改变执行结果。能力不可用或能力查询失败的目标写入明确失败原因，串行后继暂停，证据恢复不自动重投。
- 移除、换配置或取消后的迟到结果按原 requestId 留作状态记录，不能污染新成员状态或触发后续回复。
- 重启恢复历史与未完成状态，不自动重发推理、恢复群讨论或释放尚未核查的写入租约。活动 generation 退休后保留待恢复标记，实际停止和资源释放核查完成前不启动替代会话、不改绑定、不完成成员移除；丢失进程句柄不等于进程已结束。
- 重启后的停止证明须匹配唯一中断回合的 runtimeId、deliveryId 和 generation。同一原生会话前一成功回合的证明不能解锁；串行重试可插在较晚请求之前，不能按记录的数组位置推断原生执行顺序。

## 界面反馈

讨论布局和设计元素以正常聊天为准：共享侧栏、消息宽度、字体、气泡、图标、按钮和输入框，跟随聊天宽度与主题设置。成员管理通过顶部「成员」弹窗打开，状态也显示在对应回复旁。输入框让用户看清本轮 @ 目标和并行/依次模式，Enter 发送、Shift+Enter 换行。首版无工具，不提供权限提升或执行成员选择；意外工具调用在执行层拒绝并显示原因。

上下文详情在接通后显示：截至哪条消息、原文/摘要覆盖范围、原生压缩或重建、估算或实际容量来源、摘要执行者及用量。首版通过输入限制及粘贴/拖入附件时的提示说明纯文本范围，不显示写入者面板。详情按需展开，正常群聊不展示游标、generation 等实现字段。

## 实施顺序与验收

1. 首版运行链路：冻结连接的无工具策略、独立会话、协调器真实往返、停止与恢复。
2. 首版完整文本上下文与页面：固定输入、独立预算、摘要/新成员/重建和首页群聊操作，可与连接核实交错推进。
3. 首版发布：实施计划 V1-01–08 全部通过；已知核心订阅阻塞不得隐去。
4. 后续版本：工作区读工具、附件、更多平台/harness；指定成员执行另需全应用工作区租约与文件版本检查。

下表保留完整产品的场景目录；其中附件、大工具定义、工作区写入/租约与文件变化仅适用于后续版本。首版的有限发布清单为实施计划 V1-01–08，不能将本表所有场景重新加入首版；本文不表示这些测试已通过：

| 场景 | 必须满足的结果 |
| --- | --- |
| 两个相同 harness/model 的成员 | 独立身份、原生会话与游标，无状态串用 |
| 跨 harness 订阅组合 | 使用各自配置、实际可用模型与连接；不借用 API Benchmark 的结果宣称通过 |
| 并行回答期间有新消息 | 每人只确认自己的输入快照；下次补齐新消息和其他成员回复 |
| 串行回答 | 后一成员看到前一完整结果；前者失败后队列暂停 |
| 新成员或原生会话过期 | 可重建公开上下文；自身旧发言不会因 speaker 相同被错误删除 |
| 小窗口与大窗口混合 | 分别预算；大窗口设置不导致小窗口超限，当前请求不被丢弃 |
| 中文、大附件、大工具定义 | 保守计算完整开销；不可装入时给出可操作错误 |
| 摘要失败、限流或取消 | 无无限重试，不换账号/模型，不销毁原可用状态 |
| 摘要质量 | 保留约束、分歧、未完成项及来源；可回查原文 |
| 只读成员尝试写入或副作用工具 | 实际执行层拒绝；不支持此限制的组合不可伪装为只读 |
| 两群或普通会话争用同一/嵌套目录 | 应用级租约互斥，无两个写入者并发 |
| 写入期间读取、取消或进程残留 | 读写调度符合策略；确认停止前不转交租约 |
| 外部编辑或取消前已写文件 | 检测已过期文件依据，保留副作用记录，不宣称回滚 |
| 结果持久化时崩溃、请求超时后重试 | 恢复提交状态，无重复回复、错误游标或自动重复执行 |
| 移除成员、改配置及应用重启 | 无迟到事件串用，无未经用户触发的自动续跑 |

单元测试使用本地模拟驱动验证调度、预算和持久化；每个实际支持的 harness/connection 还需验证原生续聊、权限限制、停止及恢复。真实订阅或 API 冒烟单独记录环境和额度消耗，不能用模拟测试替代。
