# Provider balances and local usage

This adapter inventory was reviewed on 2026-09-15. **Usage** counts business requests routed by Camellia; **Balances & Quotas** reads account endpoints. The figures have different units and must not be added. Upstream endpoints and entitlements can change, so verify an adapter against current provider documentation before extending it.

| Provider | Account data shown | Source or limitation at review time |
| --- | --- | --- |
| DeepSeek | Available balance and returned cash/bonus components | Official `GET /user/balance`. |
| Moonshot/Kimi API | Available, cash, and voucher balances | Official `GET /v1/users/me/balance`; China and international keys are distinct. |
| Kimi Code subscription | Reported quota windows and reset times | Native Kimi Code usage endpoint; separate from Moonshot prepaid balance. |
| OpenCode Go | Five-hour, weekly, and monthly usage windows | Official service implementation of `/zen/go/v1/usage`; requires the relevant plan. |
| OpenCode Zen pay-as-you-go | No cash-balance API established in this review | Local routed usage is still available. |
| Command Code / GOAT | Credits and returned subscription/model limits | Official CLI account endpoints; Credits are not treated as US dollars. |
| Ollama Cloud | Reported subscription-window usage and per-model request counts | `/api/usage` returned 200 in a local read test but was not a documented public account API. |
| Local Ollama and custom relays | Camellia's own routed usage | A similar provider name does not authorize sending a relay key to an official provider domain. |

Configure keys in **Settings → Providers & Keys**, read the model catalog, then validate a selected model with a short request. A catalog entry alone does not establish entitlement. Usage can be filtered by provider, key, model, and date, and exported as CSV. Daily records are retained for about 90 days; the model total remains cumulative. An account balance may be shared by several keys, so the UI does not sum cards into a supposed total.

Model discovery also retains reported thinking controls and their defaults. Ollama catalogs are enriched with same-host `POST /api/show` requests, using at most four concurrent detail queries with a five-second timeout per model. Existing configured models receive updated metadata automatically without changing their context overrides. The composer, quick-switch settings and conversation model tools use reported levels rather than inferring them from model names; absent or unavailable metadata falls back to **Default / Low / Medium / High**. Ollama boolean controls are shown as **Off / On** using its OpenAI-compatible efforts (`none` / `high`). Multiple reported routes for one model expose their common supported controls. Choosing **Default** leaves the effort unset so the provider chooses its reported default.

All providers use catalog thinking/effort metadata, including DeepSeek's `effort.supported_levels` and `effort.default_level`, nested capability metadata, and account-style reasoning ladders. Models missing these controls are queried through same-host `GET /models/{id}` with configured models first, at most four concurrent requests, a five-second per-request timeout and a fifteen-second detail budget. Missing detail endpoints stop further probes; individual failures do not prevent catalog discovery. QClaw is exempt from speculative detail requests. A relay never receives another provider's credentials or inherits its documented capabilities solely from a model name.

Official MiMo endpoints use the documented boolean thinking controls for the exact V2.5/V2.6 models listed in its [Deep Thinking guide](https://mimo.mi.com/static/docs/quick-start/usage-guide/text-generation/deep-thinking.md): **Default / Off / On**, default **On**, not three independent effort levels. The router translates these switches into `thinking.type` for OpenAI-compatible requests. Official DeepSeek model catalogs omit the off control from their effort list; its [Chat Completions reference](https://api-docs.deepseek.com/api/create-chat-completion) also permits `none`, so the official adapter includes it without inventing a `medium` level.

Metadata follows the upstream model, including canonical aliases, and is invalidated when an endpoint, upstream ID or model protocol changes. API route transfers preserve these controls. Pi forwards the selected effort through its provider-request extension instead of dropping levels outside its native enum; DSH declares reported controls in its launch profile, and native boolean-off controls are translated for Ollama's OpenAI endpoint.

An optional `<router-config>.model-metadata.json` migration cache can preserve discovered thinking controls while an older running process rewrites the main configuration. Cache entries are bound to the provider ID, both endpoints, provider protocol, upstream ID and model protocol; inline metadata takes precedence, and a malformed cache is ignored. The cache contains no credentials.

Automatic account refresh defaults to 15 minutes and queries enabled providers/keys. The app stores observed trend points for about 30 days; it cannot reconstruct earlier account history. A failed refresh retains the last success with its timestamp. Missing balance, reset time, or unit is left unknown rather than inferred. Provider usage may include cached input; cached reads are a subset of input, not an extra amount to add. Failed requests with upstream-reported tokens remain attributable to the key that was charged.

Implementation: `src/api/api-usage.js` stores routed usage; `provider-accounts.js` selects adapters by real endpoint; `provider-insights.js` schedules and caches account observations without storing raw keys in its trend file. New adapters need verified authentication, units, reset semantics, and representative response tests. The Camellia brand assets live under `assets/`; `npm run build:icons` regenerates platform icon sizes from the main artwork.
