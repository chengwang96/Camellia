# Camellia Linux Server CLI

状态：设计提案与可运行的设置菜单原型。已增加[headless 与 GUI 开发入口](../linux-server-preview.md)，包含共享远程服务、本机控制、工作区/会话持久化、五引擎 driver、服务器本地订阅登录入口、独立 GUI 远程工作台及 API 设置导入，并生成 Linux x64 自包含开发包。五种真实引擎已通过 Linux 回环模型夹具测试。**真实 tailnet 双端互通及本人订阅授权仍须用户验收，不能据此宣称生产验收完成。**

CLI 设置进展：`camellia-server.cjs menu` 已提供接入真实本机控制 socket 的中英文数字菜单，包含网络配对、API 路由/默认模型、工作区与会话、语言及诊断摘要，写操作带明确确认。下面的全屏布局仍是设计原型，未实现能力不会伪装为可用；使用方式与边界见开发预览说明。

## 1. 产品边界

一个 Camellia，两种宿主：桌面 Electron 与 Linux headless。服务器不启动 Electron、不依赖 X11/Wayland，不通过虚拟显示器运行桌面包。

- Linux 设备拥有自己的工作区、独立会话、引擎进程、API 配置、订阅凭据与用量；GUI 是控制端，不是数据所有者。
- 一台 GUI 可以添加多台 CLI 设备；数据标识使用 `(deviceId, workspaceId/conversationId)`，不能把远程会话写进本机会话仓库。
- 通过内置 Tailscale 接入；登录网络后仍必须完成 Camellia 配对。Tailscale ACL 与应用授权同时生效。
- 远程工作区新建、移除，会话新建、发送、停止、审批、重命名、置顶、归档及删除使用现有控制协议的概念。
- 已配对 GUI 可主动发送本机 API 设置。订阅账号必须在服务器侧登录，绝不迁移桌面订阅 token、Cookie 或原生账号目录。
- 设置菜单先保持桌面的分类、名称与视觉身份，再增加服务器专用能力。第一版目标不是在终端重做整个聊天 GUI。

## 2. 可运行的设置设计

```sh
npm run preview:cli
npm run preview:cli -- --page network
npm run preview:cli -- --page providers --lang en
npm run preview:cli -- --plain --ascii --lang en --width 80 --height 32
node --test tests/cli-settings-preview.test.js
```

也可直接运行 `node scripts/cli-settings-preview.cjs`，只需仓库要求的 Node，不依赖 Electron 或新增 npm 包。

原型不读取用户配置、不访问网络、不持久化更改、不生成真实配对码、不接触 API 密钥。屏幕中的设备、状态、工作区和数量全是演示数据。操作入口只打开流程说明，不伪装成功。

### 设置分类

| 分类 | 内容与约束 |
| --- | --- |
| 服务商与密钥 | 服务商、端点、模型映射、密钥、导入记录；密钥默认遮蔽；服务器原生订阅登录入口 |
| 用量 | 当前 CLI 设备的请求、引擎、模型用量；不混入桌面统计 |
| 通用 | 设备名称、语言、终端外观、默认权限；所有设置注明设备范围 |
| 引擎设置 | API/订阅连接、模型、思考级别、权限；全局默认与会话覆盖分开 |
| 运行时 | 各引擎版本、可用性、安装更新、下载代理；按需安装 |
| 工作区与会话 | 服务器目录、工作区管理、独立会话；不使用本机文件选择器 |
| 已归档 | 恢复与永久删除；确认明确标注远程设备 |
| 空间清理 | 先展示清理计划与预计释放量；不清理账号、会话和网络身份 |
| 网络与设备 | Tailscale 登录/退出、配对邀请、待审批、授权列表、撤销 |
| 后台服务 | 启动/停止/重启、开机策略、运行中任务与退出语义 |
| 诊断与关于 | 版本、网络/权限/引擎检查、脱敏日志、许可证与第三方声明 |

键盘：方向键或 j/k 导航，Tab 切换区域，Enter 打开，Esc 返回，q 退出控制台。退出菜单不能误停后台服务。写操作使用独立确认，完成后显示真实结果而非乐观成功。

## 3. GUI 的设备交互

### 设备入口与布局

在工作台增加设备选择器，默认“此电脑”；添加入口写“添加 CLI 设备”。不复用“手机访问”按钮的名称，因为原来的入口是允许别人控制本机。

```text
设备 [gpu-lab-01 / CLI ▾]      在线 · Tailscale
├ 此电脑
├ gpu-lab-01
├ build-arm64
└ + 添加 CLI 设备

gpu-lab-01
  工作区                         [+ 新建工作区]
    paper-agent
      评估实验
    inference
  独立会话                       [+ 新建会话]
    环境检查

[导入本机 API 设置]  [设备设置]  [断开连接]
```

聊天标题、设置窗口、文件下载、删除确认持续标注目标设备。设备切换切换整套数据上下文，不仅切换侧栏标签。远程列表沿用桌面聊天视觉与控件；业务传输通过新的 remote adapter，不复制一个不同风格的网页聊天界面。

### 添加与连接

1. 在 CLI 的“网络与设备”登录内置 Tailscale，浏览器可位于其他电脑。
2. CLI 显示 5 分钟有效、单次使用的配对码与地址。
3. GUI 输入地址、配对码、客户端名称，经 Tailscale 发起请求。
4. CLI 本地确认客户端名称与全设备控制范围；名称不是身份凭证，仅批准自己刚发起的请求。
5. GUI 领取独立设备 token，存入系统安全存储，拉取 capability、工作区与独立会话。
6. GUI 建立列表及当前会话事件流。断线后显示最后更新时间和只读缓存，不排队写操作。

首次连接后可显示“导入本机 API 设置”入口，不自动传输。移除 GUI 中的设备只清理本地凭据/缓存；服务器撤销授权是另一个明确的操作。

### 工作区、会话和文件语义

- 新建工作区需要服务器绝对路径；沿用当前“选择已有目录”语义。若增加创建目录，必须单独确认并由服务器验证，不能把 Windows 路径传到 Linux 后自动修正。
- “移除工作区”只移除记录，不递归删除服务器文件。默认会话转为独立会话，可明确选择归档；保留原工作目录。
- 有运行、审批、Goal 或任务检查时拒绝移除，不能只检查旧的单会话 `getSession()`。
- 现有会话不能通过“移动”悄悄切换 cwd；跨目录工作新建会话。跨设备移动不在首版范围。
- 会话删除与工作区文件删除分开；永久删除会话二次确认，带设备与会话名。
- 远程路径不交给桌面本地 `openPath`；下载产物使用已授权 artifact 接口并明确本地保存位置。

## 4. API 设置单向导入

实现进展：已提供 `/v1/api-import` 与 GUI 确认流程。当前采用“整个冲突服务商保留服务器、只新增缺失服务商”的保守策略，不支持下文规划的逐项合并/覆盖选择。导入不传全局 enabled/port，不迁移 QClaw、本地端点或订阅身份；具体边界和失败恢复见开发预览说明。

按钮文案“将本机 API 设置导入 gpu-lab-01”。“本机”始终指当前 GUI 所在电脑，不因切换设备改变来源。

确认展示来源、目标、服务商数量、密钥数量、冲突项和策略，密钥值不出现在预览、日志、事件流或回执中。

- 允许字段：服务商、端点、模型映射、API 密钥及其启用状态。
- 排除字段：订阅账号、refresh/access token、Cookie、原生账号目录、监听端口、本机路径、用量、会话和设备授权。
- 默认合并：新增缺失项，冲突保留服务器设置；覆盖冲突须明确确认。身份匹配由稳定 ID 与规范化端点/模型字段组成，不能仅凭显示名。
- 全设备控制权限必需；工作区级授权不允许读写全局密钥。
- 新增 import capability 与专用写接口；不把现有只读 `/v1/api-keys` 当作上传接口。
- 写入前检查 schema、大小、URL 协议、冲突、当前版本与运行状态。首版服务器忙时拒绝应用，避免打断模型请求。
- 配置整体原子写入；若重载失败，恢复旧配置与服务状态。重复 request ID 返回原回执，不能重复导入。
- 审计只记来源设备 ID、请求 ID、时间、条目数和状态。不得将含密钥的请求原文写进命令日志。
- GUI 密钥只在主进程读取和传输，renderer 仅接收数量与回执。断开/撤销后拒绝继续写入。
- “一键”指一次导入动作，不是绕过目标确认；不经公共云中转、不依赖临时明文导出文件。

现有桌面文件导出包含 `enabled`、`port` 与 `providers`，导入是替换式配置处理。不能不加筛选地把这个现有流程复制成服务器导入。

## 5. 技术复用与必须补齐的部分

以下是对当前代码的检查结果，不代表新功能已完成。

| 当前模块 | 可复用部分 | 缺口 |
| --- | --- | --- |
| `integrations/tailnet/main.go` | tsnet、加密状态、入站反向代理 | hostname 当前固定为 `camellia-desktop`；没有供 GUI 使用的出站请求/流通道 |
| `src/main/remote/embedded-network.js` | helper 进程协议、状态、登录、监听 | 当前使用 Electron safeStorage 与 app 路径；需可注入的 headless 密钥存储、路径和设备名 |
| `src/main/remote/access.js` | 邀请、人工确认、领取 token、撤销 | CLI 本地控制台审批，以及 GUI 对端凭据存储 |
| `src/main/remote/gateway.js` | 鉴权、SSE、快照、限流、artifact 下载 | 设备元信息、增量 capability、API 设置写入与 GUI 所需管理接口 |
| `src/main/remote/commands.js` | 创建工作区/会话、发送停止、审批、重命名、置顶、删除等命令 | 尚无远程 workspace rename/delete；需并发、版本和 busy 校验 |
| `src/engines/shared-conversations.js` | 会话数据、工作区、引擎编排、Goal/任务生命周期 | 抽出独立于 Electron 主进程的 engine driver 创建与服务生命周期 |
| `src/main/main.js` | API router、引擎 wiring、运行时管理、统一设置 | 拆出 headless bootstrap，不应靠模拟 Electron API 来加载整个文件 |
| `src/renderer/chat` 与桌面工作台 | 现有视觉、会话交互与设置概念 | device context、remote adapter、远程空态/离线态/目标确认 |

### 两端内置 Tailscale 的重要限制

tsnet userspace 节点不会自动给 Electron 所在操作系统创建网络路由。因此 GUI 不能直接 `fetch(http://100.x.y.z:43127)`，然后声称内置网络已支持连接；那只在另有系统 Tailscale 路由时才可能工作。

实现进展：`integrations/tailnet/outbound.go` 已通过受 token 保护、目标固定的 loopback 反向代理接入 `tsnet.Server.Dial`。HTTP/SSE 数据流与 stdin 控制协议分离；Node `DeviceTransport` 与 `DeviceClient` 已提供有界响应解析、取消、加密凭据及配对管理。GUI/IPC 开发预览已接线，真实 tailnet 验收仍待完成。

建议扩展 helper，以 `tsnet.Server.Dial` 提供受限的出站 HTTP 与 SSE 通道。地址必须校验为批准的 tailnet 目标、固定端口、规定的 Camellia endpoint；不接受任意 URL、重定向或 proxy 环境变量。使用有界消息帧/背压/取消，避免长时间 SSE 阻塞现有串行 stdin 控制循环。不能只把完整 SSE 响应当作一个 JSON 返回。

保留 Node 网关只监听 loopback，helper 注入随机 transport token 和真实 peer 信息；不得改为 `0.0.0.0`，也不向公网开放管理端口。

### Headless 宿主与存储

建议的逻辑拆分：`core service → shared conversations / drivers / router / remote gateway`，Electron 和 CLI 各自注入生命周期、路径、安全存储、打开链接和通知能力。

- CLI 服务进程独占数据目录；交互菜单通过权限为 0600 的 Unix socket 调用本地管理接口，不能第二次独立加载并并发写同一会话仓库。
- 推荐默认目录遵循 XDG，独立于桌面预览数据；目录 0700，凭据及配置 0600。明确处理 umask、symlink 与所有者校验。
- 不将 Electron 的 `safeStorage` 替换为“永远返回可加密”的空壳。服务器优先使用用户提供的受保护密钥/systemd credential；若支持同目录本地 keyfile，应清楚说明它只提供文件权限边界，不能抵御整个目录被窃取或同用户攻击。
- 重启恢复会话列表，但不自动继续模型请求、Goal 或暂停的计划任务；遵循现有恢复/暂停规则。
- 非 root 运行。提供前台模式与 `systemd --user` 单元；SSH 退出后持续运行依赖 linger 或系统部署策略，必须在安装检查里说明，不静默提权启用。
- 首版 Linux x64/arm64；Node、tsnet helper 和实际支持的引擎一并验证。现有 tailnet build 支持 Linux 目标，不等于整个引擎栈已经支持 Linux 打包。
- 单独生成 CLI 包、校验和与第三方 notices，不向 Linux 包携带 Electron、Windows/macOS 二进制或本机账户数据。

## 6. 状态与错误设计

网络：未启动 → 需要登录 → 等待浏览器 → 已登录 → 正在监听；错误区分 helper 缺失、状态密钥不可读、节点被退出、地址变化、ACL 拒绝与连接超时。

设备：未配对 → 等待服务器批准 → 在线 → 断线/被撤销；重新连接拉取 `instanceId` 与快照，旧 instance 的写请求被拒绝。命令断线后结果不明时展示“结果待核实”，使用原 request ID 查验，不能自动重发。

危险操作：移除工作区、永久删除会话、覆盖 API 配置、撤销客户端、强制重启分别确认，不能用一个通用“确定”覆盖所有语义。错误提示给出下一步，但不回显秘密。

## 7. 实施顺序与验收

1. **本轮：设置设计原型。** 菜单、品牌、终端布局、键盘、导入/登录/配对/移除流程说明及测试；不声称提供 headless 服务。
2. **Headless core。** 抽出共享宿主，Linux 前台服务、原生订阅登录、数据目录锁、本地管理 socket；先以假引擎测试，再逐引擎验证真实运行。
3. **网络闭环。** headless Tailscale 密钥存储、设备名、登录；GUI 出站 tsnet 通道；双端配对、撤销、重连。
4. **GUI 远程工作台。** device context、工作区和独立会话、所有必需写操作、权限审批、文件访问；不改变本机工作流。
5. **API 导入与发行。** schema、冲突预览、原子写入/回滚、审计；systemd、Linux 两种架构包与真实端到端验收。

| 用户需求 | 验收要求 |
| --- | --- |
| 1. 内置 Tailscale | 干净 Linux 无桌面、无系统 Tailscale，CLI 可登录；重启保留网络身份；退出后不可连接 |
| 2. GUI 添加 CLI | 两端仅内置 Tailscale 完成配对；工作区、独立会话与本机完全隔离；GUI 重启可重连 |
| 3. 远程完整操作 | 新建/移除工作区、新建会话、发送、停止、审批、归档/删除；busy、并发、重复请求及断线失败可解释；不误删项目文件 |
| 4. 导入 API 设置 | 只上传 allowlist 字段，冲突可预览；订阅凭据零迁移；重试幂等；失败回滚；受限/撤销设备拒绝操作 |
| 5. CLI 设置一致性 | Camellia 坐姿猫、菜单术语、配色与危险确认；中英文、窄屏、无颜色、SSH、退出恢复终端 |

安全测试还需包含：未配对、已撤销、非 full-device 权限、非法目标/重定向、请求体大小、恶意控制字符、陈旧版本、密钥日志扫描、网络 helper 崩溃及双服务实例争用。

原型自动化验证覆盖布局和流程文案，但不能代替 Linux SSH 真机、systemd、真实 Tailscale 网络或供应商订阅登录验收。
