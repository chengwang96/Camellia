# SciCode full-library error audit

Report `1ba83b4f-0868-4874-a3a3-6f28eea29a1f` ran on 2026-09-16 with Ollama Cloud `deepseek-v4.1-flash`, five engines in parallel, 30 minutes, 5M tokens, and up to 40 API requests per task. Of 325 planned attempts, 18 ended before the user stopped the run at about 29.4 minutes: eight errors (all DSH), three passes, two partial scores, five stopped, and 307 still pending. Pending tasks were not failures; no engine completed all 65 questions, so there was no final aggregate score. The run recorded 224 API calls and 8,018,799 reported tokens, with incomplete usage for seven calls.

One confirmed defect was Camellia's DSH request cap of 8,192 output tokens, below the pinned native provider default of 32,768. A local fake-API reproduction returned `length` and exit code 1 under the old limit, and completed normally at 32,768. Camellia restored the native default in chat and benchmark, recorded finish reasons and native exit codes, and reports **Output limit** separately from per-task time and token budgets. It no longer displays arbitrary stderr reasoning text as an error. Six of seven unexplained historical DSH exits are strongly consistent with an 8K truncation, but those old records lack `finish_reason`; they cannot all be proven to share that cause.

The audit also found a stopped DSH draft that attempted to inspect local hidden test files. The benchmark prompt now explicitly forbids accessing local or remote hidden tests, targets, and reference answers, and limits task access to the supplied directory. This prompt is **not** operating-system isolation; an adversarial evaluation needs separate filesystem and network controls. No old score was changed, and the live run was not repeated.

`node tests/benchmark-dsh-limits-smoke.cjs` reproduces the old cap and checks the repair with a local API fixture. The broader unit tests cover truncation, quota recovery, auxiliary title requests, cancellation, budgets, and partial scoring.
