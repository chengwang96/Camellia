# 代码审查与优化记录

日期：2026-09-14。

## Kimi 第三个入口（2026-09-15）

已接入 Moonshot 官方 MIT 开源的 `@moonshot-ai/kimi-code@0.43.0`。首页新增入口，Claude 与 Kimi 通过 `src/renderer/chat/chat-runtime.js` 共用聊天界面，通过 `src/engines/session-workspaces.js` 共用工作区元数据及分页。原有 Claude 数据结构、目录和 API 线路去重逻辑保留。

`src/engines/kimi-session.js` 将真实 ACP 的会话、流式文字与思考、工具、计划和审批转为公共界面事件。支持本地文件工具、原生图片、停止、恢复、分叉、目标模式，以及重新进入 Kimi 后恢复正在运行的回复和审批。真实 Key 始终留在工作台路由中，只在同一模型线路间切换；Kimi 配置与历史使用独立 `KIMI_CODE_HOME`。

本次实际验证发现两个接入细节：ACP 的恢复/分叉忽略新 cwd，已有会话应固定目录并提供新建入口；结束进程前必须正常关闭会话，否则刚完成的一轮可能尚未保存。两者均按实际运行行为处理。Kimi 的推理菜单也只显示 ACP 返回的能力，权限使用其原生语义。

验证：80 项 Node 测试通过；真实 Kimi CLI 经本地路由完成额度切换、Read/Write/Bash、允许与拒绝、停止、续聊、分叉和图片传入；真实 Electron 验证整条界面链路、审批点击、切换入口恢复审批、修改设置后保留最新历史。Claude 工作区、分页、目标和流式渲染回归通过；共享界面和 Kimi 实际 DOM 的浅色/深色检查通过。所有模型响应来自本机测试接口，未调用付费 API。

运行时在独立 npm 包中锁定版本，附带 MIT 许可证；Electron 资源配置直接复制其 node_modules，避免打包器跳过这一目录。`scripts/check-kimi.cjs` 在缺少运行时时阻止构建，`tests/verify-package.cjs` 核对应用源码、CLI、工作线程和依赖确实进入安装包。

## 模型列表重复修复（2026-09-15）

旧设置中的 `:cloud` 模型 ID 与线路池中的统一 ID 比较时未归一，导致同一个模型重复显示。合并列表时按统一 ID 匹配，把原选中 ID 保留在对应的一行中，线路缺失时仅显示一条未配置项。不会改写用户已选模型，也不会将不同模型版本合并。

Chromium 回归先复现了 8 项模型菜单实际显示 9 项的问题；修复后验证刷新、重复线路更新、移除和恢复线路、切换模型及重载页面均通过。真实 Electron 检查通过。便携程序位于 `dist/model-list-fix/`。

## 工作台统一 API 管理

Claude 移除了端点、Token、Key 表单和模块内 API 管理按钮，模型列表改为来自工作台。主进程强制使用统一线路池，不再允许独立连接绕过路由；配置 IPC 仅收发会话设置。连接环境与 CLI overlay 复用同一份配置，overlay 写入失败时直接报告错误。清除了移除表单对应的 CSS。

78 项测试、Chromium 会话/设置流程和真实 Electron 入口检查通过。新增用例覆盖旧端点不能绕过线路池、无线路时不启动 CLI、旧 Key 不返回页面也不被覆盖；已有测试继续验证同模型轮换。新便携程序位于 `dist/workbench-api/`。DSH 源码及其他 Harness 的核实结果见 [接入方案](../design/harness-integration.md)。

## 已修复与重构

| 问题 | 改动与结果 | 验证 |
|---|---|---|
| Claude 启动失败、stdin 断开、退出码为 0 但无结果时，界面可能一直显示运行中 | 通信抽到 `src/engines/claude-session.js`，所有终止路径统一清理状态、超时器和权限请求，每轮只触发一次结束回调 | 模拟进程异常、初始化超时、重复结束、连续多轮测试 |
| 对每个 stdout 数据块独立解码会破坏跨块中文；在 exit 时读取尾部可能过早 | 使用 `StringDecoder`，在 close 后读取最后一行 | 逐字节 UTF-8、中文与 emoji、无末尾换行、exit/close 顺序测试 |
| 权限弹窗只传回“允许”，工具原输入被替换为空对象 | 主进程保留请求参数，确认时回传原参数，并拒绝过期请求 ID | 工具参数保留与重复确认测试 |
| 路由设置校验失败前，旧 Claude 进程已被终止 | 先校验新进程规格，再替换旧进程；取消操作校验进程代号 | 失败后旧进程保留、过期取消测试 |
| 长会话读取整个文件，却只展示最早 200 条消息 | 异步逐行读取，环形缓冲保留最近 200 条可读消息；原 transcript 保留用于完整续写 | 310 条消息、元数据过滤、中文及坏尾行测试 |
| 侧栏刷新重复读取会话摘要和配置，工作区分组反复扫描列表 | 摘要按路径、修改时间和大小缓存；每次列表只读取一份配置；界面先分组再渲染 | 未变化摘要只读一次，修改/删除失效，工作区 UI 回归 |
| 每个流式 delta 都重新处理整段 Markdown | 用动画帧批量渲染，结束时立即刷新尾部 | 同一批 100 个文本 delta 合为一次渲染，末尾文字不丢失 |
| 中文输入法确认键会误发送；特殊文件名预览失败 | Enter 忽略 composing 状态，文件 URL 编码 `#`、`?`；Markdown 保留字符不再造成异常 | Chromium 输入法、特殊路径和 Markdown 边界测试 |
| DSH 切回时可能重复启动后端；旧退出事件清空新进程状态 | 生命周期抽到 `src/main/backend-process.js`，相同配置共享启动 Promise 和进程；旧实例只清理自身 | 并发启动、重复启动、旧进程晚退出测试 |
| 用 HTTP 是否成功判断端口空闲，误判非 HTTP 服务 | 通过 TCP 绑定探测，支持端口 0，限制有效范围，耗尽后明确报错 | 本机非 HTTP 监听与临时端口测试 |
| 后端已退出或启动被取消后仍继续轮询；启动完成覆盖新选中的 Claude 页面 | 用 AbortController 中止探测和延时；加载 DSH 页面前再次检查当前模式 | 启动取消、超时、提前退出测试 |
| JSON 配置保存失败可能丢失原文件，损坏文件可能被默认值覆盖 | 统一 `src/shared/json-store.js`，完整写入临时文件后替换；更新配置前严格读取；兼容 BOM；错误不包含配置原文 | 写入失败保留原文件、临时文件清理、损坏配置保留测试 |
| API 配置形状错误可能被当作旧配置；状态快照能修改实际模型映射；写盘失败仍改变内存配置 | 明确校验版本与结构，清理非法计数，深拷贝公开状态，写盘成功后才替换运行配置 | 配置边界、状态隔离、持久化失败测试 |
| 上游返回 `null` 等 JSON 可能导致未捕获异常；空 SSE 被记为成功 | 校验响应结构和流起始消息，异常仅尝试同模型线路；保留 SSE 事件名，避免重复 drain 监听 | 无效 JSON、空流、原生事件名测试；原有同模型切换与部分输出不重放测试 |
| 目标的回调可能误接普通会话结果，启动前失败也扣除轮数 | 记录发起该轮的目标和进程，统一计时器引用，预检查后才记录轮数 | 普通结果隔离、工作区不可用不扣轮数测试 |
| 自定义 DSH_HOME 对部分凭据和设置读写不生效 | 统一使用用户配置目录，拒绝无效端口 | 隔离目录下的凭据写入测试 |
| 页面模板与主进程混杂；预加载订阅返回 Electron 对象；余额错误插入 HTML | 拆出 `src/main/desktop-views.js` 与 Claude HTML/CSS/JS；订阅返回取消函数；远程余额字段与错误转义 | 页面脚本编译、订阅清理、HTML 注入测试、真实 Electron 验证 |
