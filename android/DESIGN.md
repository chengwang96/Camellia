# 设计 token

App 的取值集中在一个类里：`app/src/main/java/app/camellia/mobile/Palette.java`。

它不是新的一套设计，是**把本来散在别处的取值收拢到一处**，取值一律沿用现状 —— 见下面「为什么不改值」。逐页补齐内容与布局时，先读这份，再改页面。

## 为什么有这一层

在它之前，颜色写在两个构造函数里：五个在 `ChatStyle.java`（聊天页），九个在 `SettingsStyle.java`（设置、电脑、配对页）；圆角、字号、涟漪透明度则内联在各自的调用点。改一个颜色要动三个地方，页面上每处 `setTextSize(14)` 都要自己判断这是不是正文的 14。

已经漂了一处可以佐证：`SettingsStyle.toggle` 的开关轨道 on 态硬编码了浅色的 `#4176E6`，深色模式下也是这个值（而 accent 在深色下应是 `#679EFE`）；off 态则用 `background == #F5F5F5` 反推深浅色。现在两者都直接读 token。

## 为什么不顺便改值

逐页补齐的目标是**让现有页面更好看更一致**，不是重做设计。如果 token 化顺手改了半个 app 的观感，那之后每张截图都分不清是「补齐的效果」还是「重构的副作用」，无法验收。

所以这一层只做收拢。取值要改的话，改在补齐那一页里改，并在 `PARITY` 式的地方写明理由。

## 两套色板，不是一套

`ChatStyle` 与 `SettingsStyle` 各自是**一组真实不同的值**，不是同一组的错版：

| token | 用在哪 | 浅色 | 深色 |
| --- | --- | --- | --- |
| `background` | 聊天页底色 | `#FFFFFF` | `#151517` |
| `surface` | 聊天页的块（自己的气泡、分组卡） | `#F5F6F7` | `#232324` |
| `ink` | 聊天页正文 | `#0F1115` | `#F9FAFB` |
| `muted` | 聊天页次要文字 | `#61666B` | `#ADB2B8` |
| `separator` | 悬浮栏的细边 | `#ECEEF1` | `#3B3B40` |
| `grouped` | 设置/配对页底色 | `#F5F5F5` | `#151517` |
| `card` | 那几页的卡片 | `#FFFFFF` | `#232326` |
| `secondary` | 那几页的次要文字 | `#75787E` | `#ABAEB5` |
| `divider` | 卡片内行间细线 | `#ECECEE` | `#37373C` |
| `field` | 输入框底 | `#FFFFFF` | `#303036` |
| `fieldBorder` | 输入框边 | `#B9BEC7` | `#62626C` |

首页卡片有自己的描边（浅色 `#E6E8EB` / 深色 `#34363A`），走 `Palette.homeCardEdge()`。

## 圆角

| token | 值 | 用在哪 |
| --- | --- | --- |
| `RADIUS_CARD` | 12 | 消息气泡、通用块 |
| `RADIUS_CAPSULE` | 28 | 悬浮栏、输入胶囊（不是真胶囊，是大圆角矩形） |
| `RADIUS_GROUP` | 26 | 设置卡、弹层面板、电脑行卡 |
| `RADIUS_SHEET` | 30 | 底部 sheet 的面板 |
| `RADIUS_FIELD` | 18 | 输入框、选项行 |
| `RADIUS_CODE` | 8 | Markdown 里的代码块 |
| `RADIUS_TRACK` | 14 | 开关轨道 |
| `RADIUS_GRIP` | 3 | sheet 顶部的抓手、进度条 |
| `RADIUS_HOME_CARD` | 20 | 首页卡片 |

另有一个不是圆角：**`BUBBLE_INSET` = 44**，是「自己的消息」离屏幕右边缘的距离，也是气泡允许到的最大宽度。两个方向同值，短回复和长回复才会起于同一处、止于同一处。

## 字号

`TEXT_TINY` 11 · `TEXT_SMALL` 12 · `TEXT_NOTE` 13 · `TEXT_BODY` 14 · `TEXT_INPUT` 15 · `TEXT_ROW` 16 · `TEXT_ROW_STRONG` 17 · `TEXT_DIALOG` 18 · `TEXT_CARD` 19 · `TEXT_TITLE` 20 · `TEXT_DISPLAY` 21 · `TEXT_HERO` 28

几处刻意的相邻档位：

- **14 / 16 / 17 三档**：设置页的行标题用 17（`TEXT_ROW_STRONG`），聊天页的会话名用 16（`TEXT_ROW`），首页卡片标题用 19（`TEXT_CARD`）——视觉重量刻意不同，不是随手取的整数。
- **19 与 20**：卡片标题比页面标题小一档，因为卡片在页面**之内**，用 20 会读成第二个标题。
- **13 与 15**：13 是注释级（卡片描述、说明行），15 是可交互文本（动作标签、输入框内容）。

## 首页的层级

首页是「在几种进入方式里选一个」，不是「叫用户去做某件事」。这条决定了它的视觉规则：

- 入口是**卡片**（`RADIUS_HOME_CARD` = 20），底部设置入口也是同一圆角。同一屏不该出现两种圆角的同级元素。
- 卡片的动作行是 **accent 色文字、无底色**。
- 当远程控制处于「请去手机访问」这类状态时，给出的出口按钮也**必须长成这样**（accent 文字、无底色），不能是实心强调色按钮 —— 实心按钮在页面中部会压过它上下两张卡片，把「选择题」变成「号召」。见 `MainActivity.homeEscape()`。


## 其余

- 涟漪：`RIPPLE_ON_PAGE`（页面上的行内按钮）· `RIPPLE_ON_CARD`（卡片内的设置行）· `RIPPLE_HOME_CARD`（首页卡）· `RIPPLE_ON_ACCENT_LIGHT`（强调色实心按钮）· 返回键按 `Palette.backRipple()` 取。
- 状态色：`ONLINE`（电脑可达）· `PERMISSION_STRICT`（权限档位较严时的图标色）。
- `Palette.of(context)` 取当前外观的一套；`Palette.dark` 给「需要问是深是浅」的少数几处用。

## 约定

- **页面代码不再出现字面量颜色、圆角、字号。** 需要新的档位时，先想清楚它是不是现有某一档的别名 —— 是就复用，不是才往 `Palette` 加，并写清为什么不能是现有那档。
- 同值就是同一个 token。不要为了「语义不同」造一个值相同的名字。
- 判断深浅色用 `palette.dark`，不要拿颜色和某个字面量比（那是 `toggle` 之前的老做法）。
- `PopupSurface` 是个例外：它浮在**别的页面**上，所以从采样到的颜色反推深浅，而不是问配置。

## 三种「没有东西可显示」，不要混用

界面上的「空」有三种，每一种对读者的含义不同，动作也不同：

| 形状 | 什么时候用 | 有什么动作 |
| --- | --- | --- |
| **空态** `emptyState()` | 一切就绪，只是**还没有内容**。也让读者动手做点什么 | 可选，且动作就是「创建第一项」 |
| **阻塞态** `blockedState()` | 页面**还做不了事**，缺的是前提条件 | 必须有，且动作是**去补那个前提** |
| **加载中 / 失败** | 状态在变 | 取消或重试 |

**空态不要装在分组卡片里。** 卡片在别处的含义是「这里面的东西可以点」，空态装进去就和真正的操作行同形，读者得点一下才知道它不做任何事。放在卡片外面，标题居中、没有箭头。

**阻塞态的页面，照样要保留通往解法的那个操作。** 本机聊天页在没有 API 配置时，除了说明「还没有可用的模型」并给出「前往供应商与 Key」，**列表和「新建会话」按钮必须照常渲染** —— 因为 `createConversation()` 内部本来就有一道守卫会把人送到设置页，那个按钮不是「注定失败的操作」，**它就是解法的一部分**。曾把这页改成提前 `return`，结果把唯一的前进路径砍掉了，3 个测试立刻挂（见 `LocalChatTest`）。

判据：**一个操作「当前会失败」不等于「不该显示」，要看它失败时有没有把人导向解决办法。**

## 行的右侧值

`SettingsStyle.row()` 的第三个参数是行右侧的值，`SettingsStyle.valueView()` 统一定义它的样子，**不要在别处另建一个**。

- **单行 + 省略号**。`setMaxWidth` 只限宽、不限文本行数：设备名上限 80 字符，会换行成两行，把这一行撑得比同组其他行高，右侧箭头悬在中间。
- **值要能就地更新**。`setRowValue(row, value)` 改值而不重建分组（重建会丢滚动位置）。传空串则移除该视图。
- **改值要同时改朗读标签**。行的 `contentDescription` 是「标题 + 值」，所以 `setRowValue` 一并更新它 —— 否则屏幕阅读器读的是旧状态而屏幕显示的是新状态。为此标题与值各自打了 `ROW_TITLE`／`ROW_VALUE` 标签，不要用「找第一个无 tag 的 TextView」这种依赖子 view 顺序的写法。
- **只显示同步可得的状态**。行的值要在页面构建时就有，所以不能是「起一次网络查询才知道的东西」。首页和设置索引里的网络状态因此只取 `EmbeddedNetwork.enabled()` 与 `online()`。
